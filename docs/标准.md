# ossx 标准

**crate**：`ossx` v0.1.0 · 依赖：`reqwest`、`tokio`、`hmac`/`sha1`、`quick-xml`、`bytes`、`thiserror`、`tracing`

## 1. 定位

ossx 是面向生产使用的阿里云对象存储（OSS）适配器：Signature V1 签名、对象读写、流式传输、
分片上传、预签名 URL、凭据轮换与连接池统计。零内部耦合，配置、错误、重试与并发治理全部在
本 crate 内自洽实现，不含领域模型或业务编排。

## 2. 字段治理 / 数据约定

- `ObjectKey` 是唯一合法的对象键入口：构造时校验（长度上限 `MAX_OBJECT_KEY_BYTES`、
  非法字符拒绝），数据面方法只接受 `ObjectKey`，禁止裸 `String` 直接拼 URL。
- 签名统一走 `sign_v1` / `authorization_header` / `canonicalized_resource*` 纯函数；
  新增请求路径必须复用同一签名入口，禁止手工构造 `Authorization` 头。
- multipart 分片受 `MIN_MULTIPART_PART_BYTES` / `MAX_MULTIPART_PART_BYTES` /
  `MAX_MULTIPART_PARTS` 约束；`split_parts` 是唯一分片切分函数。
- 孤儿分片经 `MultipartOrphanAudit` 审计，容量 `ORPHAN_AUDIT_CAPACITY`，超限丢弃最旧记录。
- 环境变量前缀 `FOUNDATIONX_OSSX_`，使用 `ENV_*` 常量而非硬编码字符串。

## 3. 资源治理

- 对象大小、下载缓冲、in-flight 并发、错误体字节数均在构建期校验并 clamp 到 `HARD_MAX_*`
  （如 `HARD_MAX_IN_FLIGHT` = 1024）。
- 请求与获取连接均有超时（`request_timeout` / `acquire_timeout` / `operation_deadline`），
  禁止无限等待。
- 重试指数退避 + 抖动，上限 `MAX_RETRY_ATTEMPTS`；`with_retry_deadline` 支持总 deadline。
- 错误响应体截断到 `HARD_MAX_ERROR_BODY_BYTES`，防止大响应打满内存。

## 4. 安全约定

- `AccessKeySecret` 只进入签名计算：`Debug` 输出、错误消息、日志、URL 均不得回显
  （lib.rs 有 `error_never_echoes_secret` 回归测试锁定）。
- 远程 endpoint 强制 HTTPS；HTTP 仅允许 loopback 开发端点。
- 鉴权 / 权限失败（4xx）立即返回，不重试；只有可安全重放的瞬时错误参与重试。
- STS `security_token` 与 secret 同级脱敏。

## 5. 验收

```text
cargo fmt --all --check
cargo test --all-targets
cargo clippy --all-targets -- -D warnings
cargo package --no-verify
```

热路径基准（离线）：

```text
cargo bench --bench hot_path -- --quick
```

测试至少覆盖：签名已知向量、canonicalized resource 边界（空 key / 子资源）、配置校验与
clamp、凭据脱敏回归、重试分类（可重试 / 不可重试）、`ObjectKey` 非法输入拒绝、
公开类型的 `Send`/`Sync`/`Clone` 断言。

## 6. 质量门禁约束

- crate 级 `#![forbid(unsafe_code)]`、`#![deny(missing_docs)]`、`#![deny(unreachable_pub)]`
  不得移除。
- 公共 API 面由 lib.rs 的 `public_api_surface` 测试逐一点名；新增/删除导出必须同步该测试、
  `docs/API.md` 与本文件；breaking 变更走 SemVer major + CHANGELOG。
